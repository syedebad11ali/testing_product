# Guest browse-only access: plan and completion record

Goal: **a Guest can browse properties only. Every other interactive feature needs login or signup.**
Legend: `[ ]` todo, `[~]` in progress, `[x]` done AND verified (the command and result are written beside it). Evidence tags: **[C]** confirmed from a run/source, **[A]** assumption to confirm.
Source of truth: `kpt-fianlized.zip` (565 files), extracted as `kpt/`. Phase 0 made no application change.

## A. Current-state findings (Phase 0, read-only)

**Baseline of the tree, before any change [C].** `npm test`: 234 run, 233 pass, **1 fail** (`tests/frontend/favorites.test.js`: "favorite gradients use blue in light theme, green in dark theme, and pink-red hearts"; it expects `[data-theme="dark"] .favorite-heart{-webkit-text-stroke:1px #000}` but `frontend/css/base.css:35` has `0.5px #011425`; pre-existing, unrelated to Guest access, left for the owner's decision). Backend `unittest discover`: 329 run, 1 error (`test_admin_totp`, `pyotp` missing). `npm run test:all` stops after the failing JS step, so the backend was run directly.

**How a Guest is created [C].** `POST /api/v1/auth/guest` (`backend/api/auth.py`, `services/guest_service.py`): `role='guest'` row, 15 min idle / 2 h absolute, per-IP cap `GUEST_MAX_ACTIVE_PER_IP` (default 10, `429 guest_limit`). `backend/api/auth.py::_start_session` already revokes the same browser's guest session on a successful signup/login and keeps it on failure (`tests/backend/test_guest_transition.py`, 5 tests).

**Server guard [C].** `backend/security/guards.py::login_required(allow_pending_password_change=False, allow_guest=False)`: anonymous -> `401 auth_required`; guest -> `403 guest_not_allowed` ("Create an account or log in to use this feature."). No route sets `allow_guest=True`.

**What a guest can call today (probe: every Flask route, as anonymous / guest / registered user) [C].**
* Refused to guests (401/403): **39 API routes**: messaging, my listings, listing writes, owner verification (`/api/v1/verification/check`), prefs, devices, logout-all, delete-account, all `/api/v1/admin/*`.
* Public to everyone, **including anonymous callers**: `POST /api/chat`, `POST /api/v1/chat`, `POST .../chat/feedback`, `GET .../chat/session` (`backend/api/chat.py`, **no guard**). **This is the one server-side gap for browse-only.**
* Intended public: `GET /api/v1/listings`, `GET /api/v1/listings/by-ref/<ref>`, `GET /api/v1/health`, `/api/v1/auth/{csrf,me,features,login,signup,google,google/config,forgot,reset,developer-login,dev-skip,forget-device}`.
* Pages: `/`, `/index.html`, `/listings(.html)` need a session (T4); `/messages` redirects guests to login; `/admin` redirects non-admins; `/login`, `/signup`, `/developer-login`, `/nice-try`, `/privacy`, `/chatbot-demo`, `robots.txt`, `sitemap.xml`, static assets are public.

**Interactive features with NO server API (client-only, so only the UI can gate them) [C]:** SPA views in `frontend/js/app/router.js` `VIEWS`: `verify` (per-property verification), `report`, `verlist` (My Verifications), `savedlist` (Saved Properties), `reportslist` (Report A Scam), `ownerverify`, `listing`, `verify-document` (in-browser OCR/PDF analysis incl. camera upload); save/favorite (`frontend/js/features/home.js` `data-favorite-id`, `property.js`, `state.saved` in localStorage); the Property Assistant panel (`frontend/js/features/chat.js`, FAB `#chatFab` in `index.html`, drawer entry in `features/drawer.js`, "Learn how verification works" button); home-filter preferences (`features/homePrefs.js` -> `kpt_prefs`). The embeddable widget `frontend/widget/chatbot.js` (demo at `/chatbot-demo`) is a second chat client.
**Limitation that cannot be fixed by gating [C]:** `/js/*` is public static by owner decision, so the in-browser tools and the 8 fictional sample records in `frontend/js/data/properties.js` are downloadable by anyone; gating the UI stops guests *using* them, not a determined person reading the files. The server-side owner check IS enforced.

**Existing guest UI (T4) [C].** Guest badge in the header (`features/authNav.js`), listings page hides create/mine/Messages (`js/listings-page.js`), seller chat shows an inline note with Log in/Sign up links (`features/sellerChat.js`), owner-name check replaced by a prompt (`features/ownerVerification.js`), privacy page hides the account panel (`js/privacy-page.js`). The prompts are inconsistent (different wording, no dialog).

**Google login button [C].** The responsive fix is present in this tree: `googleButtonWidth` + `ResizeObserver` in `frontend/js/auth-page.js`, `.gbox` in `frontend/css/login.css`, `tests/browser/google_button_responsive_test.py`, `tests/frontend/googleButtonWidth.test.js`, registered in `ci.yml`. Real Google sign-in is still **unverified** (stub only).

## E. Acceptance criteria
