1. No valid session -> the main login page appears first.
2. "Developer" opens a separate admin username/password page; valid authorised admin -> admin dashboard; anything else -> Nice Try page, no access.

5. Cookie-consent UI appears after a successful login (incl. Google) when no choice is recorded.
6. Pages and APIs enforce permissions server-side; direct URLs, frontend tampering and legacy bypasses give nothing.
7. Existing property features keep working.

## 14. Google button responsive fix (this run; on top of the final tree)
**Provenance.** The `karachi-property-trust-final.zip` supplied for this run did NOT contain the Google-button CSS correction, the responsive browser test or its CI registration that the request described (searched `frontend/css`, `frontend/js`, `tests/browser`, `.github`). The defect was therefore reproduced and fixed here. If another tree has its own version of this fix, compare it with the files below before merging.
**Defect (reproduced, then fixed).** With Google configured, `setupGoogle` asked Google for a fixed `width: 400` button. Google's button is an iframe of exactly that width, so on a 320 px phone (form 16-304 px) it spanned -40...360 px, on 360 px it spanned -20...380 px: clipped and off-centre (the blank white pill in the three screenshots). At 1280 px it fitted.
**Fix.** `frontend/js/auth-page.js`: `googleButtonWidth()` (container width kept inside Google's 200-400 px limits, 0 while hidden) and a `ResizeObserver` that redraws the button when the container changes (the sign-up form starts hidden; rotation/resize). `frontend/css/login.css`: `.gbox` gets `width:100%; min-width:0; max-width:100%; overflow:hidden` so the iframe can never spill out. The earlier CSS (`.btn.google`, lines 55/139) was left as is.
**Tests (actually run this run).** NEW `tests/browser/google_button_responsive_test.py`: 35 checks OK at 320/360/768/1280 px (button inside the form, width = container capped 200-400, not blank, no sideways scroll, sign-up form drawn correctly after being shown, resize 1280 -> 320 redraws with no duplicate, and the not-configured placeholder fits and explains itself). It uses a stub of Google's script (no network); it FAILS on the pre-fix code (e.g. 400 px button in a 288 px form) and passes with the fix. NEW `tests/frontend/googleButtonWidth.test.js` (3). Registered in `.github/workflows/ci.yml`; `test_ci_config` OK (6). `npm test` 224/224 (221 + 3). Browser `login`, `login_busy`, `cookies` (uses the fake Google server), `csp` OK.
